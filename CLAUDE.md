# CLAUDE.md — инструкции Claude Code

Полные правила проекта находятся в `AGENTS.md`. Этот файл является входной точкой для Claude Code.

## Проект

**Mobile Agent Русский TermuxMCP** — русскоязычный мобильный ИИ-агент для Android с локальным/облачным ИИ, Светланой, MCP/TermuxMCP, памятью, навыками, планировщиком, документами и защищённым сетевым контуром Firewall/VPN.

## Обязательные правила

1. Не выдавать каркас, mock или заглушку за готовую функцию.
2. После существенного изменения запускать соответствующие проверки.
3. Не ломать `pnpm-lock.yaml` для обхода проблем зависимостей.
4. Не использовать `git push --force` в `main`.
5. Не коммитить API-ключи, токены, cookies, приватные ключи и другие секреты.
6. Пользовательский интерфейс, документация и новые пользовательские тексты — на русском языке; английский допускается для технических идентификаторов и обязательных внешних API.
7. Не давать агенту неограниченный shell-доступ. Все действия проходят через инструменты и политики разрешений.
8. Для опасных или необратимых операций требуется подтверждение пользователя либо заранее заданная им политика.
9. `/loop` должен иметь предел итераций/времени и явную остановку.
10. `libbox.aar` является воспроизводимым артефактом и не хранится в Git.
11. Версия sing-box/libbox закрепляется commit SHA и проверяется SHA256.
12. Firewall не считается работающим до успешной инициализации реального libbox.
13. Не предполагать наличие старого `io.nekohasekai.libbox.BoxService`: текущий закреплённый AAR интегрируется через реальный `CommandServer` + `PlatformInterface`.
14. Android TUN должен создаваться настоящим `VpnService.Builder`, а дескриптор — передаваться libbox через `PlatformInterface.openTun()`.
15. Не считать успешную компиляцию доказательством рабочего VPN: нужен runtime-тест на Android.

## Архитектура агентов

- `AGENTS.md` — общие правила для любого AI-агента.
- `CLAUDE.md` — дополнительные правила Claude Code.
- `.claude/` — Claude-specific skills/hooks/команды, если они нужны.
- `agent/` и существующие MCP/skills/memory/scheduler механизмы — общий слой инструментов приложения.

Светлана, Claude и другие провайдеры должны использовать общий контролируемый Agent Orchestrator, а не собственные обходные пути доступа к устройству.

## Firewall/libbox

Текущая цепочка:

`FirewallModule → FirewallVpnService → LibboxForwardingBridge → CommandServer → libbox → PlatformInterface.openTun() → Android VpnService.Builder`

Реальный AAR подтверждён в `docs/libbox-api.ru.md`.

## Перед разработкой

- Проверить версии Expo/React Native в `package.json`.
- Изучить существующую архитектуру перед созданием нового модуля.
- Переиспользовать MCP/skills/scheduler/memory, если они подходят.
- Для native API сверяться с фактическим AAR, а не с устаревшими примерами.

## Перед завершением этапа

По возможности выполнить:

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm exec tsc --noEmit
bash scripts/verify-android-agent.sh
```

Для Android/native-изменений обязательно использовать CI с Android SDK/NDK. После получения APK нужен runtime-тест на реальном устройстве.

## Статусы

В отчётах всегда различать:

- **Проверено** — реально выполнено и проверено;
- **Реализовано, требует runtime-проверки**;
- **Каркас** — код подготовлен, но функция не подключена полностью;
- **Не реализовано**.

Не использовать слово «готово» для неподтверждённого runtime.
