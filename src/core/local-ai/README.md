# Локальный AI-движок

Единый слой для офлайн-моделей Светланы. UI и агентный планировщик не должны зависеть от конкретного inference-движка.

## Backend'ы

- **llama.cpp / GGUF** — основной универсальный backend для Android; подходит для 1B–3B моделей на устройствах с 4 GB RAM.
- **LiteRT** — backend для компактных моделей с аппаратным ускорением, когда подходящая модель и runtime доступны.
- **ExecuTorch** — резервный/экспериментальный backend для моделей, где выгодны XNNPACK/квантизация и нативный Android runtime.

## Политика для 4 GB RAM

4 GB RAM считаются минимальным классом для полноценного локального AI, но не означают, что любая 3B/7B модель будет работать. Android, UI, база данных и фоновые сервисы тоже используют память.

Поэтому менеджер моделей должен:

1. определить общий и доступный объём RAM;
2. выбрать `low`/`standard`/`high` профиль;
3. не загружать модель, если расчётный runtime memory budget превышен;
4. предпочитать 1B–1.5B Q4 на 4 GB устройствах;
5. ограничивать контекст и KV-cache на слабых устройствах;
6. выгружать модель перед тяжёлой операцией, если Android сигнализирует о низкой памяти;
7. использовать CPU как гарантированный fallback, а GPU/NPU только если backend подтверждает совместимость.

## Целевая стратегия

Для 4 GB:

`1B–1.5B Q4 → context 2048 → небольшой KV-cache → 3–4 CPU threads → streaming`

Для 6–8 GB:

`1.5B–3B Q4 → context 2048–4096 → GPU/NPU при наличии → CPU fallback`

Для 8+ GB:

`3B+ → adaptive context → аппаратное ускорение при наличии`

Размер файла модели не равен требуемой RAM: во время инференса дополнительно нужны KV-cache, runtime buffers и память самого приложения. Поэтому каталог использует отдельную оценку `estimatedRuntimeRamMb`.

## Важное ограничение

Наличие TypeScript-адаптера или модели в каталоге **не означает, что native backend уже собран**. Фактическая готовность подтверждается Android build и тестом на устройстве.
